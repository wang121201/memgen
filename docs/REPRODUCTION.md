# Acceptance procedure and evidence checklist

HBServe is the full-inference address generator. Memgen is the functional L1
(Level-1) and L2 (Level-2) cache filter. NCU is NVIDIA Nsight Compute.
`P<n>D<m>` denotes `n` prefill tokens and `m` decode steps in a batch-one
inference.

Commands are in [the runbook](RUNBOOK.md), dependencies in
[environment](ENVIRONMENT.md), and the normative gates, metric definitions and
matrices in
[the branch contract](BRANCH_AND_ACCEPTANCE_CONTRACT.md). This file is the
checklist a run must satisfy before its numbers may be called a result.

## 1. Before collecting

- `preflight.py` reports no required failure, and
  `bootstrap_vendor.py --check` reports `PASS_VENDOR_PINS_SATISFIED`.
- `scripts/verify_archive.py`, `scripts/run_cpu_smoke.sh` and both test modules
  pass. Implementation health is a precondition, never evidence.
- The point you intend to claim is declared: `collect_case.py --list-cases`.
  Decode steps `4`, `8` and `16` are not declared at all, and a prefix of a
  longer run is a diagnostic, never a substituted workload.

## 2. Freeze before measuring

Record, for the exact workload you will claim:

- model identifier, revision, precision, layer count and weight hashes;
- SGLang and package versions, batch size, tensor parallelism, eager mode and
  CUDA Graph state;
- GPU UUID, driver, and the 48-SM RTX 4000 Ada identity;
- the exact prompt and decode token ids, and the phase boundaries;
- sampler, profile, source and configuration SHA-256 values;
- phase, kernel, memory-instruction, lane-address and 32-byte-sector counts;
- three NCU repeats per claimed range and the declared aggregation rule, which
  is the median; never a single run;
- Memgen whole, prefill and decode counters over the same ranges;
- every missing or incompatible L1/L2 denominator, named explicitly.

One profile per independent point. The runtime contract these values come from
is in [branch contract](BRANCH_AND_ACCEPTANCE_CONTRACT.md) sections 3 and 4.

## 3. What a claim must report

Per `whole`, `Prefill`, the continuous `Decode` range and each `Decode<i>`: L1
and L2 read hit rate, DRAM read and write bytes with absolute and signed
relative error, request, sector and byte conservation, and the traffic formula
`100 * (modeled_bytes - NCU_bytes) / NCU_bytes`. Zero hardware traffic is
reported as absolute bytes with an undefined relative error, never as 0%.

The admission gate, the denominators, and which branch may claim what are in
[branch contract](BRANCH_AND_ACCEPTANCE_CONTRACT.md) sections 2, 5 and 6.

## 4. r4 and legacy replay boundaries

The r4 replay requires an admitted profile stream, the matching per-kernel
allocation lifetimes, the measured shared-memory context and round-robin CTA
placement. The wrapper does not invent any of that. Known modeled cross-layer
binding markers are rejected by the C++ reader whenever r4 context is requested,
including when a caller bypasses the Python wrapper, and unmarked input is not
certified as hardware-native merely because it passes that check. The
historical `--expanded` mode keeps its synthetic-address boundary and its
archived default binary path, so new callers should pass the built binary
explicitly.

`PASS_PROFILE_STREAM_CACHE_REPLAY` means the supplied stream closed, not
full-model coverage and not NCU agreement. Only separately joined workload and
range evidence can establish those. The invocations are in
[the runbook](RUNBOOK.md) section 3.3; the configuration and its limits are in
[release configuration](../release/config/README.md).

## 5. Counting rule: exact sample-profile census

The census is the aggregate count of instructions, active lane addresses and
32-byte sectors generated by an already fitted profile. When an address rule has
the same base residue modulo 32 across its CTA domain, the counter evaluates its
sector count once and multiplies by the domain size; otherwise it enumerates
every CTA as before. Exact sampled-address validation and the six published
census fields are unchanged, and the counted profiles are byte-equivalent to the
prior fitter on the tested synthetic complete, heterogeneous and sparse inputs.

This is a counting-only change: it does not improve address prediction or
hardware calibration. `python3 -B tests/sampling/test_profile_census.py` holds
the portable differential tests against per-lane byte enumeration. The direct
single-pass collector, the extended sparse fitting rules, the specialised entry
certificates and the research matrix controller remain outside `main`, and no
GPU sampling or full inference was rerun to validate it.
